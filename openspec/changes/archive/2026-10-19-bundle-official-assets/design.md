# Design

## Context

两个独立仓库分别维护知识和插件包装，现有 33 个技能与内置 MCP 配置保持兼容。源包 catalog.json 仍为中文入口事实源。

## Decisions

1. 五个官方技能分别置于对应技能的 upstream/ 下；格式技能附带固定版本的官方格式文档和工程样例。完整原文保持字节不变，不将长篇上游 SKILL.md 作为顶层发现入口。
2. 逐文件清单记录修订、原始路径、目标路径、大小和 SHA-256。更新工具从已核实的 Git checkout 导入全部跟踪文件，拒绝符号链接、依赖和缓存。
3. 旧 Bridge 文件可以作为原文快照保留，中文入口和执行示例明确仅使用原生 MCP；不新增或启动 Bridge 服务。
4. 原版脚本保留接口；格式验证器的 ajv 依赖安装在显式可写缓存，使用 NODE_PATH 调用原版 validate.js，不提交或打包 node_modules。
5. 插件同步完整技能树与摘要；安装后从实际缓存目录调用脚本，并在独立工程验证原生 MCP。没有实测的完整设计能力不由静态检查替代。

## Verification

比较官方跟踪文件与快照摘要，验证缺失/篡改和依赖污染拒绝；运行官方脚本测试、Schema 正反例、解包隔离验证及现有回归。验证实际 Codex 安装资源和原生 MCP 工程读取，记录当前客户端限制。
