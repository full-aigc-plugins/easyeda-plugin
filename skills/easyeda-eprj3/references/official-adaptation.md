# .eprj3 工程整理

官方原技能带有 init、库装载、符号/封装和布线脚本；本包现已完整携带这些脚本、模板和配套格式依赖，见 [包内资源](bundled-official.md)。优先采用当前客户端原生 API 创建工程与文档；需要离线生成时按固定上游修订取用经过许可核对的工具。

## 工程依赖

- 明确目录、工程名、板框尺寸、图页、PCB、器件和 pin/pad/network 对照。
- .eprj3 是文件夹工程，不能用旧 .eprj2 SQLite 读写方式操作。
- SYMBOL、FOOTPRINT、DEVICE 与原理图实例、PCB 实例之间的 UUID 和 pin/pad 映射必须完整。只画出外形不能代替真实电气库。
- 原技能可生成最小符号/封装，但没有自动导入任意 .elibz2 的保证。特定厂商器件需从 datasheet 与真实库核对，不能把通用模板当作已验证封装。
- 上游脚本声明默认使用 mil；不要混用原理图 API 的 10mil 坐标。

## 兼容与格式校验

原技能声明必须结合 companion 格式包，并出现过 easyeda-pro-format-skill 的旧名称。本套件对应 `easyeda-format-skill`，来源为 operations.md 中固定的官方仓库。离线生成时必须读取完整格式、Schema 与关联图元说明；技能的流程摘要不等于完整格式规范。

先用类型索引查字段，再按图元及依赖构造记录；用固定版本格式校验器验证，再在客户端打开，读取原理图网表与 PCB pad/net。不得因为文件可以打开就宣称电路正确。

## 可读性与验收

按模块组织布局，局部电路优先直接连线，跨模块标签命名一致。保存到新目录，重新打开输出工程，核对板框、器件、网络与实际库。格式验证、客户端打开、DRC 和真实制造文件检查分别报告。
